# purchase-fe Sayfa Analizi

Güvenlik modeli özeti: Çoğu sayfa `PrivateRoute` (MSAL veya geleneksel auth). `CapabilityRoute` yalnızca `/accounting` için (`ACCOUNTING_VIEW`). Sayfa içi yetkiler `authService.hasCapability(...)` ile kontrol edilir. `PublicSupplierQuote` auth gerektirmez.

## PurchaseRequests
- **Route + security:** `/purchase-requests` · `PrivateRoute` · Yetkiler: `REQUEST_CREATE` (yeni talep), `REQUEST_EDIT` (düzenle/sil), `REQUEST_VIEW` (uyarı bandı; route engeli yok)
- **Tip:** Liste (card/list satırları, klasik tablo değil)
- **Amaç:** Kullanıcının taleplerini ve onay bekleyenleri görüntüleme/yönetme
- **Form alanları:** Yok
- **Tablo / satır alanları:** Başlık, durum badge, talep sahibi, mevcut onaycı (PENDING), oluşturulma tarihi
- **Filtreler:** `Taleplerim` | `Onay Bekleyenler`
- **Aksiyonlar:** Yeni Talep Oluştur · Detay · Düzenle · Sil (confirm)
- **Modals:** Yok (`window.confirm` silme)
- **APIs:** `GET /api/purchase-requests/my-requests` · `GET /api/purchase-requests/pending-approvals` · `DELETE /api/purchase-requests/{id}`
- **Workflow/status:** Badge: DRAFT, IN_APPROVAL, APPROVED, REJECTED, CANCELLED, IN_PROGRESS, PARTIAL_APPROVAL, COMPLETED
- **Edge cases:** Düzenle: `REQUEST_EDIT` + status ≠ CANCELLED/COMPLETED · Sil: owner + `REQUEST_EDIT` + status ≠ COMPLETED/CANCELLED · `hasRestrictedRole` tanımlı ama kullanılmıyor · `REQUEST_VIEW` yoksa sarı uyarı, liste yine yüklenir

## PurchaseRequestDetail
- **Route + security:** `/purchase-requests/:id` · `PrivateRoute` · Capability’ler: `REQUEST_APPROVE`, `QUOTE_COLLECT`, `COUNTER_OFFER`, `ORDER_CREATE`, `REQUEST_EDIT`
- **Tip:** Detay + iş akışı paneli (en karmaşık sayfa)
- **Amaç:** Talep görüntüleme; belgeler; kalem/teklif; onay/red; teklif girişi; karşı teklif; siparişe dönüştürme

### Görüntülenen bölümler
1. **Başlık:** title, status, requester, current PENDING approver
2. **Talep Detayları:** description, createdAt, updatedAt
3. **Belgeler:** attachments listesi + yükleme
4. **Satın alma kalemleri** (her kalem kartı): ürün adı/kod/ID, görsel, miktar, tahmini teslim, birim, kategori, açıklama, productLink, notes, potansiyel tedarikçiler, **SupplierQuoteList**
5. **Onay Süreci:** timeline (stepOrder, status, roleName, actionTakenAt, comment)
6. **Onay İşlemi paneli** (koşullu)

### Yetki / görünürlük kuralları
| Özellik | Koşul |
|---|---|
| Onay paneli | `REQUEST_APPROVE` + status ∈ {IN_APPROVAL, IN_PROGRESS, PARTIAL_APPROVAL} + current user = PENDING approver |
| Teklif Gir/Güncelle | `QUOTE_COLLECT` |
| Karşı teklif gir / Ana teklife uygula | `COUNTER_OFFER` |
| Siparişe Dönüştür | `ORDER_CREATE` + quote.status=`RESPONDED` |
| Sil | owner + `REQUEST_EDIT` + status ≠ COMPLETED/CANCELLED |
| Belge ekle | herkese açık (auth’lu sayfa); PDF veya image |

### Onay paneli alanları
| Alan | Zorunlu | Koşul |
|---|---|---|
| nextApproverUserId | Evet (seçilebilir >1) | nextApproverCandidates |
| sendToUserId | Evet (SERKAN_BEY değilse) | `hasNoNextApprover` + sendDownCandidates |
| actionComment | Hayır | — |
| Butonlar | — | Normal: Onayla · hasSendDown: Kişiye ilet / Tamamen onayla · SERKAN_BEY+hasNoNext: Onayla ve satın almaya ilet · Reddet |

Onay payload: `{ comment, nextApproverUserId?, sendToUserId? }`  
- `completeChain=true` veya SERKAN_BEY+kişi seçilmemiş → `sendToUserId=null` (zincir sonu / satın almaya ilet)

### Modals

**1) Reddet modalı**
- Reddetme gerekçesi (zorunlu, trim)
- Geri gönderilecek kişi (SERKAN_BEY değilse): boş = tamamen reddet; adaylar = requester + önceki onaycılar
- SERKAN_BEY: `returnToUserId=null`, metin “Reddet ve satın almaya ilet” (talep kapanmaz → satın alma)
- API: `POST /api/purchase-requests/{id}/reject`

**2) Karşı teklif popover/modal**
- Adet (>0), Birim fiyat (>0)
- Sadece `RESPONDED` + `quoteUid` + henüz counter offer yok
- API: `PUT /api/supplier-quotes/{quoteUid}/counter-offer`

**3) Teklif Gir / Güncelle**
| Alan | Validasyon |
|---|---|
| unitPrice | >0 |
| quantity | >0 |
| currency | TRY/USD/EUR |
| supplierReference | opsiyonel |
| deliveryDate | zorunlu (date → `T00:00:00`) |
| validityDate | zorunlu |
| notes | opsiyonel |
- “Ana teklife uygula”: counter değerleriyle formu doldurur
- API: `PUT /api/supplier-quotes/{quoteUid}`

**4) Siparişe Dönüştür** (`ConvertRequestToOrderModal`)
| Alan | Zorunlu |
|---|---|
| quantity | Evet, 1…requestedQuantity |
| deliveryWarehouseId | Evet (aktif depolar) |
| expectedDeliveryDate | Evet, datetime-local |
| notes | Hayır |
- API: `POST /api/v1/purchase-orders` + `GET` warehouses

### SupplierQuoteList kolonları
Tedarikçi · Teklif No · (Tedarikçi: birim/miktar/toplam) · (Karşı: birim/miktar/toplam) · Teslim · Durum · İşlemler  
Durumlar: PENDING, RESPONDED, REJECTED, CONVERTED_TO_ORDER · Sıralama: seçili önce, sonra totalPrice ASC

### Belgeler
- Accept: `application/pdf,image/*`
- Upload: `POST /api/purchase-requests/{id}/attachments` (multipart)
- Download: `GET .../attachments/{attachmentId}` → blob

### APIs (özet)
- `GET /api/purchase-requests/{id}`
- `GET /api/purchase-requests/first-approver-candidates` (fallback)
- `POST .../approve` · `POST .../reject` · `DELETE .../{id}`
- `POST .../attachments` · `GET .../attachments/{id}`
- `PUT /api/supplier-quotes/{uid}` · `PUT .../counter-offer`
- `POST /api/v1/purchase-orders`
- Yan etki: PENDING onaycı sayfayı açınca `markPendingApprovalSeen`

### Edge cases
- `items` array / content / data / object.values normalize
- quotes/suppliers object→array normalize
- imageBase64 data:/http:/raw base64
- `AddItemsForm` import + `showAddItems` / `handleCancel` var ama UI’da bağlı değil (ölü kod)
- Geçersiz/eksik id → hata
- SERKAN_BEY özel onay/red yolları

## Bilinen tutarsızlıklar (edge özeti)
1. Personel düzenleme route’u eksik (`/personnel/edit/:id`)
2. PurchaseRequestDetail’de AddItemsForm / cancel UI’ya bağlı değil
3. PurchaseOrders listesinde Stoğa Kaydet sadece SHIPPED; Detail’de daha gevşek
4. AccountingOrders’ta detaya gitme yok; currency karışık toplam riski
5. Transfer UI depo/ürün isimleri yerine ID gösterir
6. SchoolType create (TR enum) vs detail display (EN enum) uyumsuzluğu mümkün
